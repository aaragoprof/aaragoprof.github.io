0614 Desplegament d'aplicacions Web URL - URI - URN Els localitzadors uniformes de recursos (URL) són el sistema per trobar recursos a internet utilitzant els diferents protocols existents. Existeix també el concepte d'identificador uniforme de recursos (URI). Teòricament, un URI és el conjunt d'un URL més un nom uniforme de recursos (URN). No obstant això, com que el concepte URN pràcticament no s'utilitza, els termes URL i URI s'han convertit en equivalents i intercanviables en la majoria dels casos.

0614 Desplegament d'aplicacions Web URL - URI - URN URI ⟶ Identifica un recurs, ja sigui pel seu nom, per la seva ubicació, o per ambdós. És el terme més ampli. Totes les URL i URN són URI. URL ⟶ Localitza un recurs, especificant on és i com accedir-hi URN ⟶ Anomena un recurs de forma única i persistent, independentment de la seva ubicació actual. No diu com accedir-hi.

Elements de la URL 0614 Desplegament d'aplicacions Web Elements principals Esquema: indica el protocol que es fara servir per accedir al recurs, segons si es HTTP o HTTPS la resta de l’URL pot tenir diferències en la seva estructura. Host: Identifica el servidor WEB, pot ser un nom de domini o una adreça IP Path: Indica la localització del recurs dins del servidor. No ha de ser necessàriament un cami físic de disc, ja que els servidors permeten crear directoris virtuals.

Elements de la URL 0614 Desplegament d'aplicacions Web Elements opcionals Port: indica el port TCP/IP per establir la connexió, per defecte es el 80 per HTTP i el 443 per HTTPS Informació d’usuari: no es part de la definició estàndar, alguns servidors permeten afegir el nom i la contrasenya per facilitar la identificació bàsica d’usuaris. Query: permet passar parametres addicionals útils especialment per a scripts o elements que executen codi al servidor. Fragment: Especifica una secció concreta dins del recurs identificat per l'URL. Aquesta part no s'envia al servidor, sinó que el navegador la utilitza un cop ha rebut el recurs sencer per a focalitzar la visualització a l'usuari.

Quan un URL és relatiu s’acostuma a anomenar path i es pot dividir en: Camins complets: comencen amb el caràcter / i especifiquen tot el directori per exemple /index.html. Camins relatius: indica on trobar un fitxer respecte al lloc on està el document actual. És a dir, no comença des de l’arrel del servidor ( / ), sinó des del directori on està el fitxer HTML actual.

HTTPS 0614 Desplegament d'aplicacions Web És un protocol de petició/resposta Tant les peticions com les respostes HTTP comparteixen una estructura bàsica idèntica: 1.Capçalera (Header): Conté metadades (informació sobre el missatge, com ara el tipus de contingut o l'estat). És alfanumèrica. 2.Cos (Body): Conté el contingut real del missatge, que pot ser alfanumèric o binari. A més, cal destacar: La capçalera i el cos estan separats per una línia en blanc. El cos és opcional; per tant, hi pot haver peticions o respostes sense contingut, només amb capçalera.

Mètodes de petició 0614 Desplegament d'aplicacions Web Mètodes de consulta Get: Sol·licitar un recurs Head: simular un GET per obtenir només metadades. Options: Preguntar quins mètodes són permesos sobre un recurs. Tracer: Diagnòstic (retornar la petició rebuda). Mètodes de Modificació Post: Enviar dades que poden modificar l’estat o les dades del servidor Put: Crear o reemplaçar un recurs senser a l’URL especificat Delete: Eliminar un recurs associat a l’URL de la petició. Connect: establir un túnel, s’utilitza per passar connexions segures SSL

Capçaleres de petició habituals 0614 Desplegament d'aplicacions Web Host: Idenfiticar el domini User-Agent: Identificar el programari client Accept: Indicar els tipus MIME de dades suportats. Accept- Language: Indicar els idiomes preferits Accept-Charset: Indicar els jocs de caràcters preferits Accept-Encoding: Indicar els tipus de compressió suportats Referer: Indicar l’URL d’origen de la petició Content-Type: Indicar el tipus MIME del cos de la petició. Content-Length: Indicar la mida del cos de la petició Connection: Gestionar l’estat de la connexió.

Codis d’estat 0614 Desplegament d'aplicacions Web 1xx: de tipus informatiu, informen el client que la petició ha estat rebuda i que el servidor continua processant la resposta. 2xx: indiquen la petició ha estat correcta i s’ha processat satisfactòriament 3xx: indiquen alguna forma de redirecció. Es dona a entendre al client que la petició és correcta però que la resposta s’ha d’obtenir d’algun altre lloc. 4xx: indiquen que hi ha hagut una errada en el processament de la petició perquè el client ha fet alguna cosa malament, l’error ha estat causat pel client. 5xx: indiquen que hi ha hagut una errada en el processament de la petició a causa d’una fallada en el servidor, l’error ha estat causat pel servidor.

Capçaleres de resposta 0614 Desplegament d'aplicacions Web Content-type: Indicar el tipus de contingut del cos de la resposta. Date: Indicar la data i hora d'enviament. Last-Modified: Indicar la data de l'última actualització del recurs. ETag: Proporcionar una etiqueta d'entitat (hash o checksum) del recurs. Server: Identificar el programari i la versió del servidor. Location: Indicar la nova adreça (URL) del recurs, s’utilitza en respostes de redirecció https://www.supermonitoring.es/blog/consultar-encabezados-redirecciones-http/

Mòduls de Apache 0614 Desplegament d'aplicacions Web La gran majoria de servidors web permeten la instal·lació de mòduls per ampliar les seves funcionalitats. Tenir funcionalitats en forma de mòdul permet adaptar millor el consum de recursos del servidor web a les nostres necessitats de producció (el servidor web només carregarà i executarà els mòduls que com a administradors tenim instal·lats i configurats). El fitxer del mòdul (habitualment el nom sol començar per mod i acabar en .so) es guarda al directori /usr/lib/apache2/modules. Per saber quins mòduls hi ha disponibles per instal·lar al servidor, amb el gestor de paquets APT podeu executar la comanda apt-cache search libapache2-mod. Es mostrarà un llistat amb el nom del mòdul i una petita descripció de cadascun.

Activació i desactivació de mòduls 0614 Desplegament d'aplicacions Web L'administració d'Apache permet tenir mòduls instal·lats però no activats. Per fer que un mòdul entri en funcionament cal activar-lo, un procés que implica fer-lo accessible des de la configuració principal. L'activació d'un mòdul consisteix a crear enllaços simbòlics (accesos directes) des del directori de mòduls disponibles cap al directori de mòduls habilitats, permetent que el servidor els carregui en iniciar-se. Es pot fer de forma manual i requereix crear enllaços simbòlics dins de /etc/apache2/mods-enabled apuntant als fitxers de configuració disponibles a /etc/apache2/mods-available També es pot fer de forma automàtica amb a2enmod [nom_del_mòdul] Un cop activat el mòdul, cal reiniciar o recarregar el servei d'Apache perquè els canvis de configuració tinguin efecte.

0614 Desplegament d'aplicacions Web Servidors virtuals El concepte de Servidors Virtuals (Virtual Hosts o vhosts, en terminologia d'Apache) permet que un únic servidor físic actuï com si fossin diversos servidors web independents, oferint llocs web diferents.

Mecanisme d'Funcionament 0614 Desplegament d'aplicacions Web El servidor virtual s'aconsegueix gràcies a la col·laboració de: 1.Protocol DNS: Permet que diversos noms de domini (p. ex., webA.com i webB.com) apuntin a la mateixa adreça IP del servidor físic. 2.Capçalera Host (HTTP): El client (navegador) envia aquesta capçalera en la petició per indicar al servidor quin nom de domini està intentant accedir. El servidor utilitza aquesta informació per saber quin lloc web específic ha de servir.

Tipus de Servidors Virtuals 0614 Desplegament d'aplicacions Web Basats en IP: S'assigna una adreça IP única a cadascun dels servidors virtuals allotjats. Basats en Nom: Múltiples llocs virtuals comparteixen la mateixa adreça IP, diferenciant-se únicament pel nom de domini especificat a la capçalera Host. (Aquest és el mètode més comú i eficient en l'ús d'IPs).

Passos per crear i posar en marxa un vhost 0614 Desplegament d'aplicacions Web 1.Aneu al directori /etc/apache2/sites-available. Aquesta carpeta conté els fitxers de configuració per a cadascun dels servidors virtuals disponibles al servidor. 2. Creeu un nou fitxer de configuració del lloc web amb el nom que vulgueu, dins del mateix directori. 3. Afegiu les opcions per adaptar-lo a les necessitats del nou servidor virtual dintre d’aquest fitxer. 4.Creeu l’enllaç simbòlic dintre la carpeta /etc/apache2/sites-enabled que apunti cap al fitxer de configuració del servidor virtual creat a la carpeta /etc/apache2/sites-available. O bé useu l’ordre a2ensite nom_fitxer_servidor_virtual.conf. 5.Executeu l’ordre service apache2 reload. Aquesta ordre força al servidor Apache a tornar a carregar la seva configuració. 6. Comproveu com respon el servidor facilitant el llocweb corresponent a cada servidor virtual.

Permisos 0614 Desplegament d'aplicacions Web Cal tenir presents algunes qüestions relatives als permisos d’accés a carpetes i fitxers: Al directori /etc/apache2 hi ha un fitxer anomenat envvars on, entre d’altres aspectes, es defineix el nom d’usuari i el grup amb el qual treballarà el servidor Apache. Per defecte trobarem: export APACHE_RUN_USER=www-data export APACHE_RUN_GROUP=www-data Això indica que el servidor Apache accedirà a arxius i directoris utilitzant l’usuari www-data i el grup www-data. Tenint en compte aquest tema, caldrà donar permís de lectura als fitxers (r–) i accés als directoris (r-x), com a mínim, a aquest usuari/grup a tots els directoris i fitxers que formin part dels llocs web que serveixi Apache.

0614 Desplegament d'aplicacions Web Mecanismes de validació general Autenticació bàsica amb fitxers: Aquest és el mecanisme més simple per implementar el control d'accés utilitzant fitxers d'usuaris i grups propis del servidor web. S'utilitzen fitxers d'usuaris i grups gestionats pel servidor web. Avantatge: Facilitat d'administració Inconvenient: Comporta una gestió diferenciada dels usuaris del servei web respecte als usuaris del sistema operatiu Autenticació mitjançant PAM: Aquest mètode integra l'autenticació del servidor web amb els mecanismes d'autenticació del sistema operatiu GNU/Linux. PAM és un sistema modular que pot comprovar múltiples fonts de credencials de forma centralitzada Autenticació mitjançant LDAP un dels mecanismes més populars i potents actualment per a l'autenticació d'usuaris en un servidor web. Pot operar de dues maneres: Integració amb el sistema central: passar la validació a un servidor LDAP que gestiona tots els usuaris del sistema, aixo ens permet una gestío unificada de les identitats Servei LDAP específic.

0614 Desplegament d'aplicacions Web El protocol HTTPS El protocol HTTP (igual que protocols antics com FTP i SMTP) pateix un problema fonamental de seguretat: tota la informació viatja en text pla (plain text). Això fa que les dades siguin fàcilment monitorables i capturables per tercers (p. ex., contrasenyes, dades bancàries o qualsevol informació privada). Per tant, l'ús d'HTTP és desaconsellable per a la transmissió de qualsevol dada sensible. El mecanisme de seguretat implementat per xifrar la comunicació HTTP és el protocol SSL (Secure Socket Layer) / TLS (Transport Layer Security) (Secure Socket Layer) L'SSL/TLS proporciona una capa de xifratge entre la capa de transport (TCP) i la capa d'aplicació (HTTP). Totes les dades que hi passen són xifrades.
